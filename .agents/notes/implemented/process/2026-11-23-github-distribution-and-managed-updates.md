# Agent Note: 公开分发 lee-ai-workflow 并支持受管理升级

Status: implemented

## Problem

用户授权用 gh 创建公开仓库 lee-ai-workflow 并推送当前工作流，其他人可提供 GitHub 地址接入，后续可用 update 升级。现有安装器只支持首次复制与同内容重复接入，没有上游来源、安装基线和升级入口；直接覆盖会破坏项目适配与局部修改。

用户进一步要求升级 Codex 中已使用本工作流或留痕入口的项目，确认项目内留痕可用后删除 Codex 全局 write-notes-like-deepseek。全局 AGENTS 的技能调用也要改成项目内规则，避免删除后留下失效依赖。

## Decision

- 上游为 `https://github.com/wobushiyoushen0214/lee-ai-workflow`，主分支 main。公开 README 提供 GitHub 地址交给 AI 的接入方式、命令行 install/update、预览和指定版本。
- 保留旧安装命令，增加 `scripts/lee-workflow.py install|update` 入口。首次接入登记 `.agents/workflow/installation.json`，记录包版本、来源及受管理文件与 AGENTS 工作流块的 SHA-256。
- 升级先准备上游副本并完成整批预检；仅替换基线未被本地改动的流程文件，只更新 AGENTS 的受管理块。`docs/workflow.md`、`workflow.config.json`、业务约定、Note、证据、发布记录和业务文件属于项目，升级保留。
- 本地修改与上游更新冲突时整批不写；无冲突时更新安装基线。无安装记录的旧项目先核对并合并，再以明确的 adopt 入口登记，不把任意旧内容当作可覆盖基线。
- Codex 已接入且未被用户排除的项目逐个读约定、保留原有未提交改动与项目命令，完成流程迁移、结构和相关脚本回归；其他项目不自动安装。项目内技能都可用后再移除全局目录，全局入口保留直接留痕纪律并引用项目规则。证据入口名采用配置以保留既有 README/report 习惯。
- 随包回归使用独立的项目适配 fixture，不将宿主业务链接与发布策略复制成测试前提；业务项目只定向运行工作流模块回归，已有失败与环境不足保留。
- 公共仓库只提交工作流本身及可公开的回归记录；本机项目迁移详情与恢复副本保留在本机，不上传业务代码或项目未提交差异。

## Alternatives considered

- 只上传文件，更新让 AI 猜：缺少可执行升级与基线，不能满足 update 的要求。
- 每次全量覆盖或强制 reset：会损坏适配表、AGENTS 业务约定和局部改动；采用摘要预检与受管理块更新。
- 把项目改动自动认作上游：下一次可能静默覆盖定制；adopt 只接管与当前包一致的流程文件，项目适配独立保留。
- 强制全局技能、全局 CLI 或包管理器：增加用户环境依赖；规则和 Python 入口随项目携带，联网升级只要求 Git。
- 删除全局技能后再修各项目：有失效窗口；先验证项目内留痕，再修改全局入口并删除。

## Validation

公开仓库已由 gh 创建；安装、受管理升级、冲突保护、回滚、独立适配 fixture 及检查器的 54 项回归通过。三个未被排除的本机项目已采用项目内规则，工作流回归各 54 项通过，业务及历史文件摘要、Git HEAD 未变；全局技能已移除，全局入口改为项目内规则与直接留痕纪律。本机迁移细节和恢复副本不进入公开仓库。

公开包原始结果与复跑方式见[分发验证](../../../../docs/ux-evidence/2026-11-23-managed-updates/README.md)。main 已推送，实际 GitHub 获取、已安装 update 的预览/应用、配置与块外约定保留和严格自检通过；本轮不验证业务产品、设备、应用发布或实际提速比例。

## Consequences

- 收益：GitHub 地址与 Python install/update 提供一致入口；安装基线让后续升级可预览、拒绝冲突并保留项目命令和记录，留痕随项目携带。
- 收益：独立测试适配 fixture 使随包回归可在已接入项目运行，避免业务链接或发布策略污染临时测试项目。
- 代价：旧版首次登记仍需核对并合并；定制通用文件与上游同时变动时需要人工取舍，不能 force 覆盖。
- 代价：联网升级依赖 Git 和 GitHub 可用性；可用已下载源目录离线升级。结构检查仍报告历史缺口，不能证明业务行为或执行耗时改善。
