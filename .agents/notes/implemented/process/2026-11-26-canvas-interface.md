# Agent Note: 决策画布界面与会话入口

Status: implemented

## Problem

用户选择 Notion 风格和明暗主题，要求移除独立 AI 输入区，在当前会话引用记录，并像 Skill 一样快速打开。界面辅助说明过多；同样的精简原则需要进入分发到项目的 AGENTS 入口。

## Decision

采用 Vetta Notion 的暖灰与克制边界，补充深色令牌；支持自动、明亮、暗黑三种外观。移除冗余说明、AI 面板与独立问题输入，保留有用状态、错误与无障碍名称。工作流 AGENTS、安装模板和设计对齐章节明确“避免不必要的次级标签和说明，让布局表达含义”。

画布打开时创建独立的引用上下文，页面“复制到会话”复制记录标题与完整路径，用户粘贴到输入框；同时保存选择，当前 Agent 使用同一上下文读取最新资料。上下文仅存服务内存，按打开会话隔离，切换工作区后随明确引用操作更新项目；不自动发送聊天消息。Skill 单独调用就打开页面，缺 MCP 的已有聊天使用随包 CLI 启动并通过同一服务读取引用。

## Alternatives considered

- Figma/Linear：用户已经选择 Notion，不再引入第二套风格。
- 保留页面 AI 助手：与当前会话分析的要求冲突，移除入口，保留后台的冻结来源和回填能力。
- 用未公开接口写入 Codex 输入框或启动另一模型会话：缺乏可靠宿主契约；使用剪贴板作为明确的主操作，结合会话引用读取；不声称自动插入原生引用卡片。
- 工作区共享一组引用：会混淆同项目不同聊天；通过每次会话打开返回的 contextId 隔离。
- 只在本仓 AGENTS 加设计原则：新接入与升级项目可能遗漏，入口模板与手册同步。

## Validation

画布 40 项测试通过，包括同项目多上下文隔离、引用读取最新来源、删除后缺失反馈、跨项目选择和打包 CLI 共享服务。明暗主题、540px 窄侧栏、搜索焦点、无 AI 输入、复制提示和清空引用已在内置浏览器检查。CLI 首次测试因测试进程未关闭 stdin 超时，修正测试驱动后通过；失败输出保留且不计通过。详细范围见 [验证记录](../../../../docs/ux-evidence/2026-11-26-decision-canvas/README.md)。

## Consequences

界面和分发规则共同采用精简原则，旧聊天也能快速打开。引用明确显示为复制操作，用户仍需粘贴到输入框；没有原生引用卡片自动插入。每个会话独立保存引用，Agent 在后续请求中读取最新资料，浏览与复制无需模型调用。

## Risks

浏览器不能直接写入 Codex 聊天输入框；复制内容需用户粘贴，或当前 Agent 在后续请求中主动读取引用。自动主题使用浏览器提供的系统配色偏好，宿主手动配色不一定同步，因此保留手动覆盖。
