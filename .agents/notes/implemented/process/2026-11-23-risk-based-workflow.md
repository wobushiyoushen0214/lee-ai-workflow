# Agent Note: 按风险精简验证与证据流程

Status: implemented

## Problem

用户反馈 AI 开发被反复核对截图拖慢，审查后明确授权修复六项流程问题。调整前的通用矩阵把视觉与交互合并为测试加截图；没有验证停止和复用条件；M/L 任务统一要求九段证据；跨文件和不确定被当作完整流程门槛；已有授权与再次确认的说明冲突；V 编号被作为验证强度排名。它们叠加后会让局部可逆改动承担不相称的设备操作和文档成本。

本次承接 [独立试用包提取](../../implemented/process/2026-11-11-portable-workflow-extraction.md) 的可移植和无覆盖接入决定，调整日常执行规则。历史原版与验证记录继续保留，不用新结果替换历史事实。

## Decision

| 问题 | 已采用的规则 | 原因 |
|---|---|---|
| 界面验证过重 | 纯视觉按适配表做静态检查与最终一次画面核对；交互、路由和状态变化跑相关断言；截图只在视觉疑点、对比或明确要求时保留 | 视觉与行为需要不同证据，截图不能替代行为断言 |
| 反复验证 | 集中修改后验证；验收标准覆盖且相关检查通过就停止；新改动影响结论、失败或环境变化时只重验受影响部分 | 同一结论重复核对不增加有效证据 |
| 重复文档 | 日常任务默认精简 README；小任务可在回复或已有 Note 记录；决策、原始输出各保留一处，其他位置引用 | 保留可追溯性，减少重复填写和同步 |
| 完整流程门槛过低 | 按行为影响、兼容性、可逆性和重要取舍判断，文件数与任务规模只用于安排工作 | 多文件小修与单文件高风险修改的风险不等同 |
| 反复确认 | 已有授权内自主推进；缺设计稿时沿用现有规范并说明假设；重大未决取舍、范围外或未获授权的不可逆动作才询问 | 常规实现选择不需要新增审批节点 |
| 追求高 V 等级 | V0–V5 保留为历史兼容的验证方式标签；交付写实际方法和覆盖范围，移除统一 ≥V3 指标 | 自动断言、画面和真实环境各回答不同问题，编号不能说明证据优劣 |

入口、手册、项目适配示例、模板、随包技能及检查器提示同步为 v1.3-portable。详细规则集中在手册 §4、§8、§9，速查和模板引用这些边界。修 bug 的开场示例采用精简或引用证据；技能目录按需创建，重要决定先 proposed，implemented 表示已落地，被否决的 proposed 转 rejected。使用现有检查器与接入回归，不新增项目依赖或截图链路。

## Alternatives considered

- 只删截图要求：不能解决停止条件、九段证据、范围判断与授权冲突，无法完整覆盖六项问题。
- 一律跳过测试与决策记录：会失去行为、契约和重要取舍的验证与追溯；只减少无增益的步骤。
- 新增自动截图、缓存框架或强制审阅 Agent：引入安装、环境和维护成本；本次问题主要来自规则边界，现有工具足够验证交付。
- 按代码行数或最高 V 编号衡量完成度：容易错判单文件高风险修改，并激励不必要的人工核对；按验收问题和证据覆盖判断。

## Validation

验证覆盖六项规则的一致性、接入与冲突保护、Note 状态和结构、本地链接、历史文件保护与包摘要。实际命令、结果、复用范围和原始输出统一见 [精简流程验证](../../../../docs/ux-evidence/2026-11-23-risk-based-workflow/README.md)。既有检查器回归和技能入口校验在受检文件未变时复用，接入文档修正后仅补对应回归。

本轮产物是流程文件；未验证真实业务项目的执行效果、设备、发布或实际提速比例。文件保留在本地工作区，未提交、推送或发布。

## Consequences

- 收益：同批视觉修改只做最终画面核对，已有有效结果可复用，避免阶段切换和整理文档触发重复设备操作。
- 收益：日常证据精简且各事实只保存一处；文件数与 V 编号不再驱动额外文档或人工核对，重要决定仍可追溯。
- 低风险判断失准：先检查影响面；重要行为、契约、权限、流程和落盘格式仍留 Note，未知重大影响需要澄清。
- 错误复用结果：只有受检代码、相关依赖、配置、数据前提和环境未受后续改动影响时才复用；构建和发布要求的最终产物核对独立满足。
- 少拍截图可能减少视觉线索：纯视觉最终核对仍保留，存在溢出、视觉疑点、差异比较或明确验收要求时按需截图。
- 文档与安装验证不能证明真实业务项目的耗时改善；本轮不虚报设备、截图、产品测试或提速比例。
