# 仓库约定

## 提交信息（commit message）

统一用 Conventional Commits 风格，一行标题：

    <type>: <说明>

- 冒号后跟**一个半角空格**；说明中英文都行；**结尾不加句号**。
- 常用 type：

  | type | 用途 |
  |---|---|
  | `feat` | 新功能 |
  | `fix` | 修 bug |
  | `refactor` | 重构（不改行为） |
  | `perf` | 性能 |
  | `docs` | 文档 |
  | `style` | 格式（不影响语义） |
  | `test` | 测试 |
  | `build` | 构建脚本 / 依赖 |
  | `chore` | 杂项 |

- 可选范围：`fix(shelf): …`、`feat(store): …`。
- 破坏性变更：标题写 `feat!:`，或正文写 `BREAKING CHANGE: …`。
- 标题 ≤ 72 字符；需要展开时**空一行**再写正文，正文用 `-` 列点。

示例：

    feat: 书城默认内置一批可用社区书源
    fix: 响应体在主线程读导致加入书架报 NetworkOnMainThreadException
    refactor: 书源解析抽成 parse()，逐条与批量共用

> 已配套 `git config commit.template .gitmessage`，`git commit` 会带上格式提示。

## 其他约定

- 文本文件里的注释、文档一律用中文（与现有代码风格一致）。
- 改完 Kotlin 先跑 `./gradlew :app:compileDebugKotlin`；涉及界面/数据库的改动尽量上真机核一遍。

## 界面文案

- 避免不必要的次级标签和说明文字，让布局本身来解释（靠层级、留白和对齐表达关系，不靠堆叠副标题、提示语和辅助标签）。

## 别跑没用的测试

**不要写、也不要跑"冒烟测试"这类没有断言价值的验证。** 具体包括：

- 装完包 `am start` 一下、看一眼 logcat 没崩就当"验证通过"；
- 为了"确认能跑"而重复执行已有的测试；
- 给一次性的临时改动补测试；
- 与本次改动无关的回归性重跑。

这些都不说明任何问题，只花时间。**要验证就跑真东西**：

- 库/引擎这类纯逻辑：`./gradlew :app:connectedDebugAndroidTest`（现有的 `SelfCheckTest`）；
- 界面改动：截图看（`adb exec-out screencap -p`），截出来的图要能直接回答"对不对"；
- 需要点击才能看到的中间状态：临时把状态强制成那个值截一张，看完**立刻改回去**。

编译过了就说编译过了，别包装成"验证通过"；没验的明说没验。

## 工作流（AI 必读）

非平凡改动一律按 [docs/ai-workflow.md](docs/ai-workflow.md) 执行（通用工作流：门禁、验证级别、模板、DoD）；
本仓库的命令/目录绑定见该文档附录 A，项目实际工作流的来龙去脉见 [docs/workflow.md](docs/workflow.md)。

三条硬门槛：

1. **先方案后动手**：非平凡改动先写 `.agents/notes/proposed/<分类>/YYYY-MM-DD-<主题>.md`；界面改动先查 `designed.md` 对应编号与令牌。
2. **编译门槛**：改完 Kotlin 必须跑 `./gradlew :app:compileDebugKotlin`。
3. **结论必须写验证级别**（编译通过 / 断言通过 / 截图核对 / 真机核对 / 未验证），验证要有 `docs/ux-evidence/` 证据；没验的明说。

交付回复按 [docs/ai-workflow.md](docs/ai-workflow.md) §17.6 的格式写：改动 / 验证级别+证据 / 未验证 / 需要确认 / 提交或发布状态。

自检：`python3 scripts/check-workflow.py`（FAIL 必须修，WARN 建议修；`--strict` 把 WARN 也当失败）。

- Note 生命周期、状态及模板以 `docs/ai-workflow.md` §5.1/§17.2 为准；归档保留 `Status: implemented`，否决使用 `Status: rejected — 原因`。
- 自检检查入口文档、Note 与嵌套证据 README 的本地文件/图片链接；`--commits N` 仅限制提交信息数量，其余检查仍全量。
- S 级纯视觉/文案可按 §17.4 合并证据 README，仍须保留截图、原始输出、复跑信息和未验证范围。
- 改动自检脚本时跑定向回归：`python3 -m unittest discover -s scripts -p 'test_check_workflow.py' -v`。
